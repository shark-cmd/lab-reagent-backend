# LabStock Mobile (Expo)

React Native / Expo client for **LabStock** — barcode-driven lab reagent & QC inventory.
Full-parity port of the web app (`../frontend`) that talks to the **same FastAPI backend** (`../backend`).
Nothing in `backend/` or `frontend/` is changed by this app.

- **Expo SDK 58** · expo-router (Drawer) · TypeScript
- **NativeWind v4** + Tailwind v3 (the web palette/typography ported 1:1)
- React Query for server state · expo-secure-store for the session
- expo-camera (barcode scanning) · expo-haptics · react-native-svg (charts + CODE128 barcodes)
- expo-file-system + expo-sharing (CSV/backup/PDF) · expo-print (label sheets)

---

## Quick start

### 1. Start the backend

```bash
cd ../backend
python run_backend_fixed.py          # mock Mongo, seeds 72 items, binds 0.0.0.0:8003
```

Seed data: 72 reagents from the HMNR Aug-2026 report. Login `admin` / `admin123` / PIN `1234`
(or `tech` / `tech123` / PIN `5678`).

### 2. Point the app at it

`mobile/.env` (values are **inlined at bundle time** — restart Metro with `-c` after editing):

```ini
EXPO_PUBLIC_API_URL=http://localhost:8003
```

| Where you run the app | Value |
|---|---|
| Web / iOS simulator on this PC | `http://localhost:8003` |
| Android emulator | `http://10.0.2.2:8003` |
| Physical phone (same Wi-Fi) | `http://<host-LAN-IP>:8003` (find it with `ipconfig`) |

The backend already binds `0.0.0.0`, so a phone can reach it. Make sure Windows Firewall
allows inbound TCP 8003.

### 3. Run the app

```bash
npm install
npx expo start -c          # then press w (web), a (Android), i (iOS), or scan the QR in Expo Go
```

All native modules used here (`expo-camera`, `expo-secure-store`, `expo-haptics`, `expo-print`,
`expo-sharing`) work in **Expo Go** — no dev build required for v1.

## Notable port decisions

- **Camera scanning** uses `expo-camera` (`CameraView` + `onBarcodeScanned`) instead of `html5-qrcode`.
- **Haptics** use `expo-haptics` instead of `navigator.vibrate`.
- **Downloads** (items/history CSV, JSON backup, PO PDF) download with the auth header via
  `expo-file-system` and open the OS share/save sheet (`expo-sharing`) — the mobile equivalent of
  the web's blob download.
- **Barcodes** are generated by a small built-in CODE128-B encoder (`src/lib/code128.ts`) rendered
  with `react-native-svg` for the on-screen preview, and emitted as inline SVG in the printable
  label sheet (replacing the web's jsbarcode + `window.print`).
- **Charts** are hand-rolled `View`/SVG bars (no Skia/linear-gradient native deps).
- **Dense web tables** became card rows (the sensible phone layout) while keeping every field and action.
- Light theme only (`userInterfaceStyle: "light"`), matching the web app's default.

## Build & update (EAS)

```bash
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest update:configure
npx eas-cli@latest update --channel production --environment production -m "message"
```

`eas.json` uses `cli.version ">= 27.5.0"`, `appVersionSource "remote"`; iOS `resourceClass` is
`default | medium | large` (`m-medium` is invalid). **Before shipping**, set
`EXPO_PUBLIC_API_URL` to a reachable HTTPS URL via `eas env:set` (Android release builds block
cleartext `http://`) and confirm it was inlined:
`findstr /s /m /c:"<host>" dist\*`.

EAS project: `@drsaifbiochems-team/labstock` · Android package / iOS bundle id:
`com.drsaifbiochems.labstock` · `EXPO_PUBLIC_API_URL` is set for the `preview` and `production`
EAS environments.

### Update branch / channel

| | |
|---|---|
| Branch | `production` |
| Channel | `production` (points at branch `production`) |
| Runtime version | **`exposdk:58.0.0`** — `runtimeVersion.policy` is set to `sdkVersion` |
| Update group | `238c0d54-156b-49a0-bacf-104acfd95a87` |
| Platforms | android, ios |

`runtimeVersion.policy` **must stay `sdkVersion`** for updates to reach Expo Go. Expo Go SDK 58
requests `exposdk:58.0.0`; with the older `appVersion` policy the same update was published as
`1.0.0` and the CDN returned 404 for it. Only change the policy if you stop previewing in Expo Go.

Open the published update in Expo Go (the channel is required — without it the CDN returns 400):

```
exp://u.expo.dev/f6bd6853-c55d-4e10-b71e-c20047e74b68?channel-name=production
```

Republish after a change:

```bash
eas update --branch production --environment production -m "message"
```

Verify what the CDN is actually serving (expect `200`, your update group ID, and `launchAsset`):

```bash
curl -s -o /dev/null -w "%{http_code}\n" "https://u.expo.dev/f6bd6853-c55d-4e10-b71e-c20047e74b68" \
  -H "expo-runtime-version: exposdk:58.0.0" -H "expo-channel-name: production" \
  -H "expo-platform: android" -H "Accept: multipart/mixed"
```


## Troubleshooting

- **`Uncaught Error: Cannot manually set color scheme, as dark mode is type 'media'` on web.**
  NativeWind defaults `darkMode` to `media`; react-native-css-interop's web runtime then calls
  `colorScheme.set('system')` when it injects the stylesheet and throws. Fixed by setting
  `darkMode: 'class'` in `tailwind.config.js` — do **not** remove it. The app is light-only
  (`app.json` `userInterfaceStyle: "light"`) and never adds the `dark` class.
- **`EMFILE: too many open files` from Metro.** A dev-server file-handle limit (common when several
  other dev servers are running on the machine), not an app bug. Restart Metro; if it persists,
  raise the limit (`ulimit -n` on Unix) or close other watchers.
- **`eas build` fails with `EPERM … backend/.pytest_cache_temp` while "Compressing project
  files".** EAS archives from the **git root**, not `mobile/`, and that leftover pytest cache
  directory has a deny-all ACL that neither git nor EAS can read. Remove it once with an
  elevated shell (`takeown /f backend\.pytest_cache_temp /r /d y` then
  `Remove-Item -Recurse -Force backend\.pytest_cache_temp`), or run EAS from a checkout that
  does not contain it. Ignore files (`/.easignore`, `/.gitignore`) do **not** avoid it, because
  the archive walker stats the path before applying them.
- **Login fails only on a physical phone.** `localhost` on the phone means *the phone itself* —
  point `EXPO_PUBLIC_API_URL` at the host's LAN IP or the deployed HTTPS URL, and check
  Windows Firewall allows inbound TCP 8003.
- **`.env` edits have no effect.** `EXPO_PUBLIC_*` is inlined at bundle time; restart Metro with
  `npx expo start -c`.
